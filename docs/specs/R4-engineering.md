# R4 — Engineering Hardening

**Status:** Draft · **Effort:** ~1 day · **Depends on:** none (R3.4 session-restore
coordinates with R4.2's keyed widgets)

## Motivation

Nothing here is user-visibly broken enough to jump the queue, but each item is a latent
failure or a growing tax:

1. **Suspected bug — "Load into Mix A" may not update the sliders.** The Compare sliders
   are unkeyed; Streamlit ignores changed *default* values once a widget has state, so
   writing `st.session_state.mix_a` and rerunning may leave the sliders (and therefore
   the metrics) showing the old mix. The AppTest smoke only asserts "no exception" and
   cannot catch it. Unverified — verification is step one.
2. `app.py` is ~800 lines across 8 tabs with a fragile "Config block must run first"
   ordering protected only by a comment (flagged in the earlier altitude review).
3. CI runs tests only — no lint (CLAUDE.md names ruff), no coverage floor.
4. No comparative evidence for the four backends (flow/GA/ACO/NSGA) — users pick on vibes.

## 1. Slider state propagation (verify, then fix)

### Design
- **Verify first** with an AppTest that (a) sets a slider, (b) simulates the recipe-load
  path by writing the target keys, (c) reruns, (d) asserts the slider `.value` changed.
- Fix by giving every mix slider an explicit key (`f"{param}_{key}"`, e.g. `cement_A`)
  whose canonical value lives in `st.session_state`; "Load into Mix A/B" and session
  import write those keys directly; `st.session_state.mix_a` becomes derived
  (assembled from the widget keys each run) rather than parallel state. Presets go
  through the same path — one write mechanism, no divergent copies.

### Acceptance gates
- AppTest: after a simulated load, slider values equal the loaded recipe and the Mix A
  metrics reflect it.
- Existing smoke + session-import tests stay green.

## 2. Modularize `app.py`

### Design
- New `ui/` package: `ui/config.py`, `ui/compare.py`, `ui/inverse.py`, `ui/pareto.py`,
  `ui/calibration.py`, `ui/workflow.py`, `ui/reference.py` — each exposing
  `render(ctx)`.
- `AppContext` dataclass (in `ui/context.py`): `predictor`, `bayesian`, `costs`,
  `carbon_kwargs`, `use_advanced_chemistry`, `exotic_strength_enabled`, `robust`
  (post-R1). Built by `ui/config.py` **explicitly before** the other renderers are
  called — replacing the comment-guarded "Config tab's `with` block is written first"
  ordering with an actual dataflow dependency. `app.py` shrinks to page setup, sidebar,
  `ctx = render_config(...)`, then the tab renderers.
- Pure logic stays in `src/ui_logic.py`; `ui/` holds only Streamlit wiring. No behavior
  change intended — the AppTest suite is the regression harness for the move.

### Acceptance gates
- All existing tests green; AppTest still exercises every tab.
- `app.py` under ~100 lines; no `ui/` module imports another tab's module.
- Grep gate: the "must run first" ordering comment is gone (the dependency is now code).

## 3. CI hardening

### Design
- Add `ruff check .` as a CI step with a minimal `ruff.toml` (start from defaults +
  line-length 100; fix or `noqa` the existing findings in the same PR — no drive-by
  refactors).
- Add `pytest --cov=src --cov-fail-under=70` (floor chosen below current coverage;
  ratchet later rather than blocking on day one).
- Document the binary-artifact policy in `README.md`: committed artifacts
  (`models/*.json`, `support.npz`, `amortizer/`, ~5 MB) are regenerated by
  `python -m src.models` / `python -m src.amortized` and are committed *together*; if
  the repo outgrows this, move to git-lfs or release assets (decision deferred, policy
  stated).

### Acceptance gates
- CI green with both new steps on this branch.
- `ruff check .` clean locally.

## 4. Backend benchmark table

### Design
- `scripts/benchmark_backends.py`: for targets {25, 45, 65} MPa × backends
  {flow (if trained), GA, ACO} and one NSGA run, measure: mean |achieved − target| of
  the sample cloud, cloud spread (per-parameter std), % in-support, wall-clock time.
  Fixed seeds; ~2–3 min total budget.
- Output a markdown table written to `docs/BENCHMARKS.md` (committed, with the command
  to reproduce and the machine caveat); link it from `docs/WORKFLOW.md` §1 so "when to
  use which" is backed by numbers.
- Not part of CI (timing-sensitive); a fast smoke test asserts the script runs and
  emits the expected columns with tiny budgets.

### Acceptance gates
- `docs/BENCHMARKS.md` exists with the four-backend table and reproduction command.
- Script smoke test green.

## Out of scope
- Performance profiling of the Streamlit render loop; git history rewriting to shrink
  old binaries; multi-page `st.navigation` migration (the tab layout stays).

## Risks
- The modularization (4.2) is the riskiest refactor in the set — mitigate by moving one
  tab per commit with the AppTest suite run between moves, and by doing it *after* the
  slider-key fix so widget keys move exactly once.

## Implementation notes (sonnet-ready)

### The Streamlit keyed-widget pattern (R4.1, and reused by R3.4) — READ THIS FIRST

The failure mode: writing `st.session_state[key]` *after* a widget with that `key` has
been instantiated in the same script run throws
`StreamlitAPIException: st.session_state.<key> cannot be modified after the widget ... is
instantiated`. Passing both `value=` and relying on a pre-set `session_state[key]` is also
wrong. The working pattern:

1. Give every mix slider a stable key: `st.slider(..., key=f"{param}_{slot}")`
   (e.g. `cement_A`). **Do not pass `value=`** — let Streamlit persist under the key.
2. Initialise the keys once in the state-init block:
   `st.session_state.setdefault("cement_A", 300)`, etc.
3. To "Load into Mix A" / apply a preset, write the keys via an **`on_click` callback**
   (`st.button("Load into Mix A", on_click=_load, args=(rec,))`). A value written inside a
   callback lands *before* the widgets instantiate on the following rerun — this is the
   only clean way to set a keyed widget programmatically.
4. Derive the mix vector from the keys each run:
   `mix_a = np.array([st.session_state[f"{p}_A"] for p in PARAM_NAMES])` — drop the
   parallel `st.session_state.mix_a` copy so there is one source of truth.
5. **Verify with a value-propagation AppTest**, not a crash-only smoke: set a key, call
   the load callback path, `.run()`, and assert the slider `.value` and the Mix-A metric
   both changed. A "no exception" assertion will pass even if the bug is present.

### R4.2 modularization

- **Mechanical moves only** — no logic edits in a commit that moves a tab. Run the full
  unit + AppTest suite between every move. Behaviour drift here is silent; the AppTest
  suite is the harness, so keep each move small enough that a failure localises.
- `AppContext` is *built by* `render_config()` and passed into the other renderers as an
  argument — that argument dependency is what replaces the comment-guarded "Config runs
  first" ordering. Delete the comment; the dataflow now enforces it.

### R4.3 ruff

- Run `ruff check .` once and triage in the SAME PR: fix trivial findings (unused imports,
  f-strings without placeholders) and `# noqa` the intentional ones (e.g. `E402` after the
  `pytest.importorskip`/path setup in tests). **Do not refactor logic to satisfy lint.**
  If the count is large, scope ruff to `src/` + `tests/` first and add `app.py`/`ui/` once
  R4.2 has split it.
