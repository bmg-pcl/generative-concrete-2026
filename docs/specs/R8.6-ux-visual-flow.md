# R8.6 — UX & Visual-Flow Release

**Status:** ready for parallel dispatch
**Process:** DELEGATION_WORKFLOW.md v2 — partition by **exclusive file ownership**, never by finding.
**Evidence base:** every issue below was observed on real renders — the app run headless
(`streamlit run app.py --server.headless true`) and screenshotted tab-by-tab via Playwright,
including one full live GA run on the Pareto tab. Nothing here is speculative.

## What this release is — and is not

This is a **presentation and flow** release. It restructures *how* information is shown;
it must not change *what* is computed or *whether* it is disclosed.

Non-negotiable constraints (repeat these in every dispatch prompt):

1. **No disclosure may be deleted.** The honesty surface — "(advisory)", "(experimental)",
   "(heuristic)", basis labels, slump caveats, UNKNOWN semantics — is a project invariant.
   Moving a caveat behind a popover/expander is fine; removing or softening its text is not.
2. **No numeric behavior changes.** No edits to `src/` computation paths, optimizer code,
   or `CONFIG_DEFAULTS` values. `compute_metrics` / `recommend_recipe` / GA/NSGA outputs
   must be bit-identical. (The single exception: WP-U2 may edit *presentation-string
   helpers* in `src/ui_logic.py` — see its scope.)
3. **Keyed-widget rules stand** (see `ui/state.py` docstring): widget key IS the value,
   never `value=` alongside `key=`; programmatic writes happen in callbacks or before
   widgets instantiate; no duplicate widget keys across tabs.
4. **The `ctx` dataflow stands**: `render_config` executes first in `app.py` and returns
   the `AppContext` every other tab consumes. Reordering *tab labels* is fine — the
   `with tab_config:` block already runs first regardless of its visual position — but the
   execution order must not change.
5. Streamlit is **1.61**: `st.popover`, `st.badge`, `st.container(border=)` are available.

## Test policy (FIRST line of every dispatch prompt)

Run tests **in the foreground only, with an explicit timeout**, and only the targeted
files named in your WP. Never run the full suite; never background a test run and wait
on it. The orchestrator owns the full-suite gate.

- Baseline on `main` (7c089c1), measured by the orchestrator: **see
  `baseline.txt` handed with your dispatch** (recorded at dispatch time; the suite was
  511 passed / 1 skipped at the R8.5 merge).
- Primary UI gate: `tests/test_app_smoke.py` (streamlit AppTest, runs every tab's code

- `tests/test_ui_logic.py` guards the presentation helpers WP-U2 touches.

### WP-U1 — Navigation, guide consolidation, calibration status

**Owns:** `app.py`, `ui/sidebar.py`, `ui/workflow.py`, `ui/calibration.py`

Observed problems:
- The sidebar guide says "**1. Config** … These apply everywhere", but Config is the
  **5th tab** — users land on Compare Mixes with defaults they never saw.
- The Workflow tab is a second, longer copy of the same guidance (two canonical guides).
- The sidebar guide expander is `expanded=True` on every run, permanently spending
  ~300 px of every tab.
- The Calibration tab shows nothing about current overlay-dataset state before an upload
  (is a calibration already loaded? how many rows?).

Deliverables:
1. **Reorder tabs** in `app.py` to match the numbered workflow:
   `Config, Compare Mixes, Inverse Design, Pareto Optimization, Calibration, Workflow, Technical Report, References`.
   Keep the `with tab_config:` block executing first (it already does — only the label
   list order and variable naming change). Update the sidebar guide numbering if needed.
2. **One canonical guide**: shrink `ui/workflow.py` to what the sidebar does *not* say —
   keep the "three questions, three tools" table and the §-level decision guidance,
   drop the step-by-step duplication; the sidebar keeps the short numbered steps and
   points at Workflow for depth (it already does).
3. **Sidebar guide auto-collapse**: expanded on first script run of a session, collapsed
   thereafter (a plain `st.session_state` flag set after first render; no widget-key
   tricks needed — `expanded=` is not a keyed value).
4. **Calibration status line**: at the top of the Calibration tab, state whether an
   overlay dataset is currently loaded and its row count, or "No calibration data loaded
   — the model is running on the base UIUC dataset alone." Read whatever the existing
   calibration path already exposes; do **not** add new persistence.

Acceptance (extend `tests/test_app_smoke.py` — you own no test file exclusively, so add
a clearly-named test function; smoke tests are append-only for other WPs too, conflicts
are label-disjoint):
- AppTest: tab labels appear in the new order.
- AppTest: app runs clean; the calibration status text is present.

### WP-U2 — Compare tab: disclosure hierarchy & compliance presentation

**Owns:** `ui/compare.py`, `src/ui_logic.py` (**presentation-string helpers only** —
`slump_caveat`, `compliance_advisory_text`, and any new pure string/formatting helpers.
No touch to `compute_metrics`, `carbon_for_mode`, `recommend_recipe`, fitness, or
compliance *logic*. `tests/test_ui_logic.py` must stay green.)

Observed problems:
- Under each metric column sits an undifferentiated grey caption stack: 90 % interval,
  tensile basis, curing basis, and a long slump heuristic-fallback paragraph
  **duplicated verbatim under both columns**. Every caveat has equal weight, so none
  registers.
- The "Cross-jurisdiction compliance (advisory)" table renders FAIL/FAIL for ordinary
  default mixes (representative-class heuristic) with no plain-language framing and no
  exposure class selected — it reads as "your mix is illegal" on first contact.
- UNKNOWN and FAIL are not visually distinguished in the table.

Deliverables:
1. **Caption hierarchy**: keep one short line per metric (value + basis chip, e.g.
   "slump ~9.5 cm · heuristic basis"); move multi-sentence caveats behind `st.popover`
   (or an expander) — full text unchanged inside.
2. **Dedupe shared caveats**: when A and B carry the identical caveat (the slump
   fallback paragraph), render it once, full-width below the two columns, not twice.
3. **Compliance framing**: above the cross-jurisdiction table, one plain sentence:
   which representative class each row was checked against and that selecting a real
   exposure class in Config is what makes the verdict meaningful. Collapse the table
   in an expander (collapsed) when **no** exposure class is selected; expanded/open
   when one is.
4. **Distinguish UNKNOWN from FAIL** visually (e.g. neutral/grey vs red text or badge) —
   semantics untouched (UNKNOWN never counts as PASS).

Acceptance:
- `tests/test_ui_logic.py` green (foreground, timeout).
- AppTest additions: the shared slump caveat string appears **exactly once** in the
  Compare tab's rendered output for the default mixes; compliance framing sentence
  present; app runs clean.

### WP-U3 — Pareto tab: run feedback, results layout, chart legibility

**Owns:** `ui/pareto.py`

Observed problems (from a driven live run, 30 generations):
- Pre-run, the right column is **entirely empty** — major layout imbalance.
- During the run, the only feedback near the button is a bare progress bar; all charts
  stream in below the fold.
- On completion, the success banner + metric cards land mid-page (page grew
  1571 → 4459 px); the user must scroll to discover the run finished.
- "Optimization complete! Best Fitness: −11.38" and a **Best Fitness −11.38** metric
  card expose a unitless negative internal scalar as a headline number.
- Objective Weights sliders have cryptic incommensurate scales (Strength 0–2,
  Carbon at 0.05) with only `?`-tooltips.
- "Evolution of Best Solution Metrics" stacks **three right-hand y-axes**; Carbon and
  Cost axes collide and a tick clips.
- The "Philosophical Note" promises **violin plots** ("watch the blobs shrink") but the
  gene-pool chart renders box-and-whiskers.
- The multi-paragraph essays sit as raw body text at the bottom of a working tab.

Deliverables:
1. **Pre-run placeholder** in the right/results area: one bordered container explaining
   what will appear ("Charts stream here generation-by-generation once you run"), so the
   column is never blank.
2. **Live feedback at the controls**: generation counter + current best strength/carbon/
   cost (or best fitness *labeled as internal score*) rendered next to the progress bar
   during the run.
3. **Completion summary near the button**: banner + the four metric cards render at/near
   the top of the results area, not mid-stream. Replace the headline "Best Fitness"
   metric with the three physical metrics; if fitness stays visible anywhere, caption it
   "internal weighted score (higher is better)" — do not present a bare −11.38.
4. **Weights help text**: one caption under the Objective Weights header explaining the
   scales and that they multiply normalized penalty terms (read the actual formula in
   `scalarized_fitness` and describe it truthfully — do not invent units).
5. **Evolution chart**: replace the triple-y-axis figure with three stacked subplots
   sharing the x-axis (`plotly.subplots.make_subplots`, `shared_xaxes=True`).
6. **Text/chart mismatch**: either render the gene-pool distribution as actual violins
   (`go.Violin`) or fix the essay text to say box plots — one or the other, not both.
7. **Essays into expanders**: the "Philosophical Note …" block moves into a collapsed
   expander ("How the optimizers work") — text verbatim.

Acceptance:
- AppTest additions: app runs clean; the placeholder text exists pre-run; no bare
  "Best Fitness" metric label without the internal-score caption. (AppTest can't click
  "Run Live Optimization" through a real GA cheaply — do **not** add a full-run AppTest;
  verify the run path by hand once with a short `Generations=3` run via
  `streamlit run` if needed, and say so in your report.)
- `tests/test_generative.py` and `tests/test_nsga.py` green (you must not have changed
  optimizer behavior — these prove it).

### WP-U4 — Inverse Design tab: recipe presentation & robust-mode framing

**Owns:** `ui/inverse.py`

Observed problems:
- The recommended recipe renders as one unstyled run-on text line of eight numbers.
- The robust-mode result shows "+17.4 vs target" as a green delta badge with no adjacent
  explanation — it reads as an overshoot *error* (the point estimate exceeds the target
  *by design* because the guaranteed lower bound is what met it).
- "Load into Mix A" / "Load into Mix B" buttons are oddly far apart.

Deliverables:
1. **Recipe as a table/metric grid**: kg/m³ per material (+ age) in a compact
   `st.dataframe`/`st.table` or metric row — not a text line.
2. **Robust framing**: when robust mode is on, caption the strength result:
   "target met at the guaranteed lower bound; the point estimate is higher by design"
   (adapt wording to what `recommend_recipe` actually returns — read it, stay truthful).
   When robust mode is off, no change.
3. **Adjacent load buttons**: the two Load buttons side-by-side in one row
   (`st.columns(2)` directly under the recipe), same callbacks.

Acceptance:
- AppTest additions: app runs clean; recipe table element present after a (cheap,
  GA-backend, small-budget) inverse run **only if** an existing AppTest already drives
  one — otherwise assert statically renderable elements only and verify the run path
  by hand as in WP-U3.
- `tests/test_amortized.py` green (proves no behavior change on the backends you
  render).
